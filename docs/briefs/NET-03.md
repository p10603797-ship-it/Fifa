# NET-03 — Room codes, share links, lobby flow
Owns: `src/net/lobby.ts`, `src/net/roomCode.ts`. Contracts: src/contracts/input.ts (InputFrame, INPUT_FIELDS), app.ts (TickInputProvider, MatchSetup, SessionControl), tuning T_NET, src/sim/core/serialize.ts (packFrames, serializeState), hash.ts (hashState), clone.ts. Your stub was created by FND-04 (read src/net/*). BRIEF §11 1v1 online: "Build this last. Nothing else may depend on it, and local play must work with the network code removed." Transport is PeerJS (peerjs 1.5.5) over WebRTC data channels with the free public PeerJS broker and default ICE servers, settings in one config object; no keys; only a nickname and inputs are sent; no chat, no accounts. Deterministic lockstep with input delay (3 ticks initially, adaptive 2-8), inputs on an unordered channel with the last 10 frames repeated in every packet, lobby/pause/resync on a reliable channel, late input holds the sim with a small waiting indicator and never guesses, desync guard: state hash every 30 ticks, host sends a snapshot on mismatch, guest hard-syncs, both log seed/tick/inputs. Tests must not touch the public network: inject a fake transport (in-memory pair with configurable latency/jitter/loss from NET-08). Flow: "the host taps Create Room and gets a 6-character code and a share link. The friend enters the code
or opens the link. Both pick teams and ready up. The host owns the match settings."
Implement: roomCode (6 characters from an unambiguous alphabet (no 0/O/1/I), generation (app side may use crypto.getRandomValues), validation, share link
`<origin><path>?room=CODE` and parsing on boot), lobby state machine over the reliable channel: hello (nickname, GAME_VERSION/SIM_VERSION -> version
mismatch error), host settings (MatchConfig template: clubs, kits, half length, rules, difficulty n/a), team picks, ready flags, start (host sends the final
MatchConfig with seed; both start), cancel/leave; timeouts with plain-language errors.
Tests: code alphabet/validation, link parsing, lobby message flows on the in-memory transport (both ready -> start with identical configs; version mismatch;
leave).
