# NET-02 — PeerJS transport, channels, config
Owns: `src/net/transport.ts`, `src/net/config.ts` (+ `src/net/types.ts` for the NetTransport interface). Contracts: src/contracts/input.ts (InputFrame, INPUT_FIELDS), app.ts (TickInputProvider, MatchSetup, SessionControl), tuning T_NET, src/sim/core/serialize.ts (packFrames, serializeState), hash.ts (hashState), clone.ts. Your stub was created by FND-04 (read src/net/*). BRIEF §11 1v1 online: "Build this last. Nothing else may depend on it, and local play must work with the network code removed." Transport is PeerJS (peerjs 1.5.5) over WebRTC data channels with the free public PeerJS broker and default ICE servers, settings in one config object; no keys; only a nickname and inputs are sent; no chat, no accounts. Deterministic lockstep with input delay (3 ticks initially, adaptive 2-8), inputs on an unordered channel with the last 10 frames repeated in every packet, lobby/pause/resync on a reliable channel, late input holds the sim with a small waiting indicator and never guesses, desync guard: state hash every 30 ticks, host sends a snapshot on mismatch, guest hard-syncs, both log seed/tick/inputs. Tests must not touch the public network: inject a fake transport (in-memory pair with configurable latency/jitter/loss from NET-08).
Implement: config.ts (one exported config object: PeerJS host/port/path/secure for the public broker defaults, ICE servers = PeerJS defaults, timeouts;
replaceable for a self-hosted PeerServer), types.ts (NetTransport: open(role, code), sendInputs(packet), sendReliable(msg), onInputs, onReliable, rtt,
close, events for connected/disconnected/error with typed reasons), transport.ts using peerjs: host creates a Peer with an id derived from the room code
(prefix + code), guest connects; two DataConnections: 'inputs' (reliable: false, ordered: false — or serialization 'binary' with unreliable options as
PeerJS supports) and 'control' (reliable); binary packing of input packets (Int16Array via packFrames + tick header); error mapping to plain-language
reasons (broker unreachable, code not found (peer-unavailable), room full, version mismatch (handshake), connection blocked (ICE failure timeout)). No
network use at module load.
Tests: unit with a mocked Peer/DataConnection (no real network): packet encode/decode round trip, error mapping, reconnect handling; an in-memory
transport implementation for other NET tests (export it from `src/net/memoryTransport.ts`, which you own too).
