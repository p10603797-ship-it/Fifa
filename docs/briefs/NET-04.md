# NET-04 — Adaptive delay, redundancy, round-trip measurement
Owns: `src/net/adaptive.ts`. Contracts: src/contracts/input.ts (InputFrame, INPUT_FIELDS), app.ts (TickInputProvider, MatchSetup, SessionControl), tuning T_NET, src/sim/core/serialize.ts (packFrames, serializeState), hash.ts (hashState), clone.ts. Your stub was created by FND-04 (read src/net/*). BRIEF §11 1v1 online: "Build this last. Nothing else may depend on it, and local play must work with the network code removed." Transport is PeerJS (peerjs 1.5.5) over WebRTC data channels with the free public PeerJS broker and default ICE servers, settings in one config object; no keys; only a nickname and inputs are sent; no chat, no accounts. Deterministic lockstep with input delay (3 ticks initially, adaptive 2-8), inputs on an unordered channel with the last 10 frames repeated in every packet, lobby/pause/resync on a reliable channel, late input holds the sim with a small waiting indicator and never guesses, desync guard: state hash every 30 ticks, host sends a snapshot on mismatch, guest hard-syncs, both log seed/tick/inputs. Tests must not touch the public network: inject a fake transport (in-memory pair with configurable latency/jitter/loss from NET-08).
Implement: RTT measurement (ping/pong on the reliable channel every 500 ms, smoothed with jitter estimate), input delay controller (delay = clamp(ceil((rtt/2
+ 2*jitter) / tickMs) + 1, 2, 8) with hysteresis; changes agreed via the reliable channel at a future tick so both peers switch on the same tick), redundancy
(every input packet carries the last 10 frames: encoder/decoder with de-duplication by tick), packet loss tolerance.
Tests: controller behaviour on synthetic RTT series; both peers switch delay at the same tick; redundancy recovers 5% loss without stalls in the in-memory
harness at 80 ms each way, 20 ms jitter.
