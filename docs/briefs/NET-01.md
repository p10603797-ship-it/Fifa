Your stub was created by FND-04 (read src/net/*). BRIEF §11 1v1 online: "Build this last. Nothing else may depend on it, and local play must work with the network code removed." Transport is PeerJS (peerjs 1.5.5) over WebRTC data channels with the free public PeerJS broker and default ICE servers, settings in one config object; no keys; only a nickname and inputs are sent; no chat, no accounts. Deterministic lockstep with input delay (3 ticks initially, adaptive 2-8), inputs on an unordered channel with the last 10 frames repeated in every packet, lobby/pause/resync on a reliable channel, late input holds the sim with a small waiting indicator and never guesses, desync guard: state hash every 30 ticks, host sends a snapshot on mismatch, guest hard-syncs, both log seed/tick/inputs. Tests must not touch the public network: inject a fake transport (in-memory pair with configurable latency/jitter/loss from NET-08).
Implement createLockstepProvider(opts): TickInputProvider for two humans where the local human's frames are sampled from local devices and scheduled for
tick + delay, sent through a transport interface (define `NetTransport` in `src/net/types.ts`? — owned by NET-02; until present define a minimal local
interface and align via a change request), remote frames buffered by tick; ready(tick) true only when both frames for tick exist; take() fills both; local
frames for the first `delay` ticks are neutral; stall reporting (waiting flag + duration); frame history kept for redundancy and resync; deterministic
ordering independent of arrival order.
Tests (with an in-memory transport): both peers produce identical frame streams and identical sim hashes over 3,000 ticks with random latency/reordering/
duplication; stall when a remote frame is missing; no guessing.
